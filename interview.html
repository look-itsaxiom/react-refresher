Take the front-end track

Years of React beats three weeks of Go in a round that rewards reading speed.

A debugging hour rewards fluency in the language you read fastest, not the one you most want to prove. Nothing to install also removes a whole class of morning risk. Tickets can reach into data and the API either way; on this track your code changes stay in TypeScript and React.

The one exception: if the front-end codebase turns out to be a framework you have never touched, such as Angular or Vue, Go with Docker Compose is the fairer fight. Ask which framework it is the moment you sit down.

The first ten minutes

Orient before you fix. Their words, not mine.

"I'm going to spend a few minutes orienting before I touch anything."

  1. Read the README and the package.json scripts. Note dev, test, and build.
  2. Start the app and the test suite. Both running beats either one perfect.
  3. Say the folder shape out loud: where routes live, where components live, where data fetching lives.
  4. Open one representative component top to bottom so you know the house style.
  5. Note the state library, the data layer, and how strict the TypeScript is. These decide where bugs hide.
  6. Read all four tickets before fixing one. Say which you will start with and why.
  7. Name what you are deprioritizing.

"I'm starting with ticket 2 because it blocks the others. I'll come back to the styling one last."

A loop you can narrate

One line to say at each step. Long silences are hard to read.

Network tab, then component state, then the render.

A log, a breakpoint, or a failing test that proves it.

Rerun the repro and the tests.

Where React bugs hide

Symptom first, then the tool that confirms it.

Stale closure in an effect or callbackAn old prop value is captured.React DevTools, then log the value at the top of the callback.
Missing effect dependencyFires once, never updates.the lint warning, then log the dependency array.
Keys by array indexState sticks to the wrong row after reorder or delete.DevTools highlights; reorder the list by hand.
Derived state duplicated in stateTwo sources of truth drift apart.search for a useState initialized from a prop.
Async race on selection or unmountA resolved fetch sets state after you moved on; the previous item shows.a labeled log in the .then with the id it resolved for.
Wrong branch in a reducerThe action falls through to the default.log the action type and the next state on every dispatch.
Off-by-one in paginationPage 2 starts a row late, or the last page is empty.network tab query params against the row count.
Date parsed as UTCA YYYY-MM-DD string slips a day.log the raw string next to the formatted one.
Strict equality against a JSON idThe API sends "12", the code compares to 12.log both values with typeof.
Optional chaining hiding a nullThe screen renders blank instead of erroring.remove the ?. for a moment and see what throws.
Fetch without an error branchA 500 becomes an empty list.network tab first, then look for a missing res.ok check.
Memoized value with wrong depsA memo or callback never recomputes.React DevTools Profiler, "why did this render".
Controlled versus uncontrolled inputTyping does nothing, or a warning about switching.check whether value is ever undefined.
A labeled console.log beats staring at code, and reaching for one without apology reads well. A failing test that reproduces the bug is the strongest confirmation you can show.

Where full-stack bugs hide

A UI ticket may need a look at the data to explain it.

Response shape versus what the UI expectsA renamed or nested field.compare the network payload to the TypeScript type.
Status code mismatchA 200 carrying an error body, so the happy path runs on garbage.the response body in the network tab.
The data is simply wrongNot every ticket is a code bug.the JSON file or one SELECT.
Missing filter or reversed relationAnother user's rows, or predecessor and successor swapped.count requests and read the query params.
Timezone at the boundaryStored UTC, rendered local, or the reverse.the raw value on each side of the boundary.
Stale cacheThe list lags one action behind after a mutation.watch for the missing refetch in the network tab.
Missing auth headerWorks on one screen, 401s on another.request headers side by side.
Environment configA base URL or flag differs between dev and the running app.print the config at startup.
To look at data fast without leaving the track: copy the failing request from the network tab as cURL and replay it with one parameter changed, or write a one-line test that calls the data function and asserts the shape. If Postgres is in Compose, docker compose exec db psql and one SELECT beats guessing.

Questions to ask the room

They are teammates, not examiners. Asking early is a signal, not a cost.

  1. What is the intended behavior here? The ticket says what is wrong, not what right looks like.
  2. What are the exact repro steps, and does it happen every time?
  3. Which environment did this come from, and is there a user it happens for?
  4. Is there a recent change that touched this area?
  5. Do you want the root-cause fix now, or the safe fix now and the refactor filed?
  6. Which of these four matters most to you today?
  7. What is your definition of done: passing tests, a manual check, or both?
  8. Is there anything about this codebase that surprises people in their first week?

"I'm not sure.""I have two hypotheses. I'm testing the cheaper one first, with a breakpoint here."

Tonight

Test the setup the day before, not the morning of.

  • VS Code with a JavaScript debug terminal, plus launch configs for Node and Chrome. Set one breakpoint tonight to prove it attaches.
